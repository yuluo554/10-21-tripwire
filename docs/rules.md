# 18 条归因规则（人类可读）

> **机器可读的权威清单是 `src/tripwire/rules/rules.json`**；数值口径（族与计数、门禁三数、
> `fingerprint`、退出码）的唯一真相源是 `data/README.md` 第六节。本文是**人的阅读副本**，
> 只解释"谓词在判什么、为什么这样判"，不复述第二份数值。
> 谓词实现 = `src/tripwire/rules/predicates.py`；归因流程 = `src/tripwire/rules/engine.py`。

---

## 一、归因怎么走（读这张表之前先看四条）

1. **一条差异可能像多条规则** → 按 `id` 升序取**首条**，其余进 `evidence.also_matched`（K6）。
   "还像什么"本身是证据，不静默丢弃。
2. **规则只给候选阶段**（`possible_stages`），真正的环节由**快照序列筛出来**：
   从 `stage-0` 起逐阶段比这个单元格，找到首次出现 `got_text` 的那一步。
3. **观察到变化的阶段名不在候选里** → 按实际运行顺序取候选中最早的；**候选与本次 run
   的阶段名无交集 → 降级 `unclassified`**（D1：宁可 unclassified，不伪造归因）。
4. **归因上限是"环节"，不是"代码行"**。工具能证明"值在 `stage 1` 变成这样"，
   不能证明"是 openpyxl 的 `%.16g` 那一行"。

`--explain` 的日志格式（写死）：

```
rule=<name>, first_seen_at=stage 1 (excel_com_csv), candidates=[...] -> resolved to excel_com_csv
```

括号里是**实际**首次观察到变化的阶段；`resolved to` 后面是规则候选里选中的那个。
两者不同不是 bug，恰恰是最有信息量的情形。

## 二、数值族（8 条）

| # | 规则 | 判据 | 正例 | 反例（必须**不**命中） |
|---|---|---|---|---|
| 1 | `leading_zero_lost` | 原文有前导零（长度 ≥2 且以 `0` 开头）、往返后数值相等但零没了 | `02114` → `2114` | `0` → `0`（单个 `0` 不是前导零）；`007` → `007`（零还在） |
| 2 | `scientific_notation_coercion` | 原文纯数字串、往返后是科学计数法、**数值等价** | `123456789012345` → `1.23457E+14` | `ABC123` → `1E5`（原文非数字串）；数值不等的情况归 #4/#5 |
| 3 | `float_precision_truncated` | 原文**定点小数**（必须带小数点）、往返后有效位变少且**数值不等** | `1.005` → `1.00` | `19.90` → `19.9`（数值相等 → #7）；纯整数不走这条 |
| 4 | `int53_overflow` | 原文整数绝对值 > 2^53−1，往返后**不等** | `12345678901234567890` → `1.23457E+19` | `9007199254740991`（=2^53−1）→ 同值 |
| 5 | `excel_15_digit_truncation` | 原文整数有效位 > 15，往返后 ≤15 位，且**恰好等于原文按该位数四舍五入的结果** | `12345678901234567890` → `1.23457E+19` | `openpyxl_csv` 跑出的 16 位科学计数法（有效位 16） |
| 6 | `negative_zero_sign_lost` | 原文是负零（`-0` / `-0.0`…），往返后符号消失 | `-0.0` → `0` | `-0.5` → `-0.5`（非零值） |
| 7 | `decimal_trailing_zero_dropped` | 原文小数有尾随零、往返后**数值相等**但文本更短 | `19.90` → `19.9` | `19.9` → `19.9`（无尾随零） |
| 8 | `exponent_form_normalized` | 两侧都是指数形、写法不同（大小写 / 补零 / 加号）且**数值相等** | `1e-7` → `1.00E-07` | `1e-7` → `2e-7`（数值不等） |

### #3 与 #5 为什么必须写得很窄

这两条是"按 id 抢首条"最容易踩到的位置：

- **#3 不收纯整数**：`12345678901234567890` 在 Excel 里走的是 15 位截断。若 #3 也认它，
  它（id 3）会抢在 #5（id 5）前面；而 #3 的 `possible_stages` **不含** `excel_com_csv`，
  于是随后"候选阶段无交集"会把一次真实的 Excel 截断降级成 `unclassified`——
  把一个已看清的形态写成"没规则认识它"。
- **#5 要求"恰好等于四舍五入结果"**：只说"变短了"会把"随便改了个数"也算成 Excel 截断。

### 数值比较一律经 `Decimal`

`float('12345678901234567890') == float('1.23457E+19')` 是 **True**。用 float 比较会把
"真的丢了位"读成"相等"，#4 / #5 就永远不命中，归因会悄悄变成 `unclassified`。
`predicates.as_decimal()` 是唯一切入点。

## 三、空值族（2 条）

| # | 规则 | 判据 | 正例 | 反例 |
|---|---|---|---|---|
| 9 | `empty_vs_null_vs_missing` | 空串 / null 字面量 / **缺格** 三者之一变成另一种 | 缺格 → `""`（空串）；`""` → `NULL` | `0` → `""`（原文不是空态；"值被清空"落 unclassified） |
| 10 | `null_token_collision` | 原文是 `NULL` / `N/A` / `NaN` 等字面量，往返后塌缩成缺失 | `NULL` → `""` | `NULLY` → `""`（字面量不匹配） |

**"缺格"靠 `DiffRecord.orig_missing` / `got_missing` 区分**（M2 加的字段）：缺格与空串的
文本都是 `""`，只看文本这一族永远不命中。这是 M3 依赖 M2 的唯一一处硬耦合。

`NULL_TOKENS` 刻意**只收跨引擎都算缺失的那一小撮**（`NULL` / `N/A` / `NA` / `NAN` /
`NONE` / `#N/A` / `#NA` / `NIL` / `<NA>`）。不用 pandas 的 19 项完整列表：
"是不是 null token"不该取决于某个引擎的实现细节。

## 五、时间族（4 条）

| # | 规则 | 判据 | 正例 | 反例 |
|---|---|---|---|---|
| 15 | `date_retyped_to_text` | 原文 ISO 日期，往返后变成另一种文本日期形态，且**目标日期真实存在** | `2024-01-02` → `2024/1/2` | 两侧同形；`1900-02-29` → `1900/2/29`（目标不存在 → 归 #17） |
| 16 | `date_system_shift_1904` | 两个可解析日期恰好相差 **1462 天**（1900/1904 纪元之差） | `2024-01-02` → `2028-01-03` | 差值是别的数（普通格式变化） |
| 17 | `serial_60_phantom_date` | 往返后渲染出 `1900-02-29` —— 那天不存在，是 Excel 1900 闰年 bug 的产物 | `1900-02-29` → `1900/2/29` | `1900-02-28`（serial 59）→ 不命中 |
| 18 | `number_format_dropped` | 值没变，但 `number_format` 语义丢了（`0%` / `@` 变 General） | `0.15`（`0%`）→ `0.15`（General） | 拿不到 `number_format`（见下） |

### #15 与 #17 的边界

`1900-02-29` 不是"换了个写法的日期"，是假日期。`parse_date()` 对它返回 `None` 是**刻意的**
（`datetime.date(1900, 2, 29)` 本来就会抛 `ValueError`）——所以幽灵日期只能由 #17 按文本识别，
不会被误当成合法日期参与 #16 的天数差计算。#15 因此显式要求"目标日期可解析"。

### #18 当前恒为 `False`（如实登记，不假装覆盖）

`number_format` 是**单元格级元数据**，四条 CSV 通道都**不产出**它（CSV 里根本没有这个东西）。
所以 `stage_meta` 里没有 `orig_number_format` / `got_number_format` 时，本谓词返回 `False`，
这类差异落 `unclassified`。

这不是缺陷，是 D1 的落法：**没有证据就不归因**。`test_number_format_rule_needs_stage_meta`
把这条事实钉住。二期若接入 xlsx 读回通道，把格式塞进 `stage_meta` 即可让本规则生效，
**不需要改谓词**。

## 一、分层架构

```
┌──────────────────────────────────────────────────────────────┐
│ 入口层  cli.py（argparse 子命令）→ exitcodes.py（0/1/2/3）     │
├──────────────────────────────────────────────────────────────┤
│ 编排层  run.py（一条命令串起 M1→M2→M3→M5）                     │
├───────────────┬───────────────┬───────────────┬──────────────┤
│ 管线层 M1     │ 差异层 M2     │ 归因层 M3     │ 报告层 M5     │
│ pipeline/     │ diff/         │ rules/        │ report/       │
│  stage 执行   │  对齐+结构    │  18 条谓词    │  md/json/sarif│
│  文本快照     │  DiffRecord   │  stage 筛选   │  首屏三段     │
└───────────────┴───────────────┴───────────────┴──────────────┘
                    ▲                       ▲
                    │ 夹具生成 M4           │ 门禁 M4
              fixtures.py ──────────── gate.py
                    │
              ┌─────┴──────────────────────────────┐
              │ 基础层：serialization.py（唯一写盘）│
              │        csvio.py（原文读写，不过 pandas）│
              └────────────────────────────────────┘
```

**四条分层红线**：

1. **写盘单点**：一切产物落盘走 `serialization.write_json / write_text`（`sort_keys=True, ensure_ascii=False, indent=2` + LF + 结尾换行 + 原子写）。任何模块不得自行 `open()+json.dump()`。判别 = "换个子命令，写盘形态会变吗？"
2. **快照读原文**：`csvio` 只做**文本行/单元格切分**，不经 pandas。pandas 只在管线阶段内部使用（D6）。
3. **规则是纯函数**：`rules/predicates.py` 内每个谓词签名 `(orig, got, declared_type, stage_meta) -> bool`，禁止网络 / 时钟 / 随机 / 文件系统读取。
4. **先算一次再渲染三次**：`report/model.py` 持有内存结果对象，MD/JSON/SARIF 三个渲染器只读它，不各自重算。

## 二、统一中间表示（IR）

| IR | 字段 | 产生者 | 消费者 |
|---|---|---|---|
| `StageMeta` | `stage_index, stage_name, columns[{name,declared_type}], rows, cols, sha256, runtime{pandas_version,dtypes,excel_version,excel_build,openpyxl_version,sqlite_version}` | M1 | M2 / M3 / M5 |
| `DiffRecord` | `row_key, col, col_index, orig_text, got_text, orig_missing, got_missing, declared_type, stage_index` | M2 | M3 / M5 |
| `StructureRecord` | `kind ∈ {row_count, col_count, col_order, header, dtype_drift}, detail, stage_index` | M2 | M5 |
| `Attribution` | `rule, first_seen_at, first_seen_stage, candidates[], resolved_stage, evidence{orig,got,also_matched[],stage_meta}, fingerprint` | M3 | M5 |
| `RunResult` | `run_id, pipeline, stages[], diffs[], structures[], attributions[], gate{recall,precision,unclassified}, verdict` | 编排层 | M5 |
| `Gate` | `stage_name, recall, precision, unclassified, expected, reported, matched, missing[], unexpected[], wrong_rule[], passed, vacuous` | M4 `gate.py` | M5（首屏 `GATE:` 行） |

`RunResult` 是**唯一**跨模块载体；渲染器不得回头读 `runs/` 目录（否则"三份同源"只能靠纪律，不靠结构）。

## 三、依赖选型

| 依赖 | 版本基线 | 用途 | 缺失时行为 |
|---|---|---|---|
| Python | **3.10+**（本机 3.12.10；3.8 通道不保证） | 运行 | — |
| `pandas` | ≥ 2.2（本机 3.0.6） | `pandas_csv` 阶段、`--batch` dtype 漂移 | 该阶段**显式失败**，不跳过 |
| `openpyxl` | ≥ 3.1（本机 3.1.5） | `openpyxl_csv` 阶段 | 该阶段**显式失败** |
| `pywin32` / COM | 可选，仅 Windows | `excel_com_csv` 阶段 | 该阶段**显式失败并记录 `excel_unavailable`**，不回落 openpyxl |
| 标准库 | `sqlite3`, `json`, `csv`, `hashlib`, `argparse`, `unicodedata` | 其余全部 | — |
| `pytest` | ≥ 8（开发 extra） | 测试 | — |

**零网络**：不引入任何 HTTP 客户端依赖；测试里用 AST 扫描断言 `src/tripwire/**` 不 import `requests/urllib.request/http.client/socket`（`socket` 仅允许出现在 `selftest` 的"未使用"说明中——首期干脆全禁）。

**依赖分层**：`[project.dependencies]` 只放运行期真实 import（pandas、openpyxl）；`[project.optional-dependencies].dev` 放 pytest。CI 必须**同时**跑 `pip install -e .` 与 `pip install -e ".[dev]"`，防止"本机碰巧装过"。

## 四、退出码通道

定义唯一来源 = `data/README.md` §6.3；代码侧单点 = `src/tripwire/exitcodes.py`。

| 码 | 语义 | 谁产生 |
|---|---|---|
| 0 | 无损 | `run --expected` / `report` / `gate` 判定 |
| 1 | 有损 | 同上 |
| 2 | 门禁失败（recall/precision/unclassified 任一不满足） | 同上 |
| 3 | 用法错误 / 拒绝运行（无主键、声明非法、缺依赖、**没有真值因而不判定**） | 全入口 |

**判定通道 = 0/1/2，用法通道 = 3，两者不混用。** `argparse` 的 `SystemExit(2)` 必须在 `cli.main()` 内统一捕获并**转成 3**——否则"参数写错"会被读成"门禁失败"（本机实测坑，见 SKILL.md）。

**0/1/2 只出自"真算过门禁"的出口**（D18 的 M5 细化）：`run` 不给 `--expected`、`diff`、
`attribute` 都拿不到 recall / precision，因此一律走 3 并明说"不产出有损/无损判定"
——报 0/1 等于把"没验过"写成"验过了"。

## 五、确定性纪律（跨模块）

| 编号 | 纪律 | 落点 |
|---|---|---|
| K1 | 快照存原始文本（`stage-<k>.csv`），不存 DataFrame | M1 |
| K2 | `run_id = sha256(pipeline_name \| input_sha256 \| decl_sha256)[:16]`，不含时间戳 | M1 |
| K3 | `excel_com_csv` 与 `openpyxl_csv` 是两个 stage 名，报告只写实际跑的 | M1 |
| K4 | 无 `--key` 且 `--align key` → exit 3，不产出任何差异结论 | M2 |
| K5 | 差异排序 = `(row_key, col_index)`，两次运行逐字节一致 | M2 |
| K6 | 规则谓词纯函数；一差多命中按 `id` 升序取首条，其余进 `also_matched` | M3 |
| K7 | `unclassified` 单独计数、单独列出，可 `--fail-on unclassified` | M3 |
| K8 | 生成器不读时钟、不用全局 `random`（自研 splitmix64） | M4 |
| K9 | 报告渲染不读时钟 / 随机；三格式同源 | M5 |
| K10 | `fingerprint = sha256(row_key \x1f col \x1f rule)[:16]`，不含 run_id/路径/时间 | M5 |
| K11 | 一切 JSON 落盘走 `serialization.write_json`（排序键 + `ensure_ascii=False` + LF + 结尾换行 + 原子写） | 全局 |

**验收方式**：K1/K2/K5/K8/K9 各有一条"同输入双跑逐字节 `cmp`"测试；K4/K7 各有一条退出码测试；K11 有一条 AST 守门（禁止 `src/tripwire` 内出现裸 `json.dump(`）。

## 六、构建与打包

- `pyproject.toml`（setuptools 后端，`src/` 布局）：`[project.scripts] tripwire = "tripwire.cli:main"`。
- 版本号**单一来源** = `src/tripwire/__init__.py::__version__`；`pyproject.toml` 用 `dynamic = ["version"]` + `[tool.setuptools.dynamic] version = {attr = "tripwire.__version__"}`，**杜绝两处手抄**（SKILL 阶段 7 C 节的"四处一致"在 Python 侧的落法）。
- 发布形态（M6）：`python -m build` 产 sdist + wheel；**附件口径 = sdist + wheel + `SHA256SUMS`**（纯 Python 包无平台产物），`SHA256SUMS` 由 CI 生成并作为第三个附件上传，digest 同时登记在 Release 正文与 `plan/RELEASE-M6.md` §2.2。
- 包数据：`src/tripwire/rules/rules.json` 必须进 wheel（`[tool.setuptools.package-data]`），并配一条测试"装好的包里 `importlib.resources` 能读到 18 条"。

## 七、目录形状（终态）

```
src/tripwire/          # 包本体（进 wheel）
  cli.py  exitcodes.py  serialization.py  csvio.py  fixtures.py  gate.py
  pipeline/{schema,runner}.py  pipeline/stages/{pandas_csv,excel_com_csv,openpyxl_csv,json_sqlite_csv}.py
  diff/{align,engine}.py
  rules/{rules.json,predicates.py,engine.py}
  report/{model,render_md,render_json,render_sarif}.py
tests/                 # 不进 wheel
pipelines/             # 三份声明样例（进 sdist）
fixtures/golden/       # 金样本（进 sdist）
docs/                  # 三份文档（进 sdist）
tools/                 # 布局门 / 脱敏门（不进包，进仓库）
plan/                  # 计划套件（不进包）
data/README.md         # 口径真相源（不进包）
```

**"进包 / 不进包"是两套集合**：

| 集合 | 内容 | 判据 |
|---|---|---|
| wheel（运行必需） | `src/tripwire/**`（含 `rules/rules.json`） | 装好后 `importlib.resources` 能读到 18 条规则 |
| sdist（**自足**：解包后 README 的每条命令都能真敲） | `src/` + `pipelines/` + `fixtures/golden/` + `docs/` + `plan/` + `tools/` + `tests/` + `README.md` + `AGENTS.md` + `data/README.md` | 解包树里跑 `tools/` 两门与 `pytest` 都能绿 |
| 只留在仓库 | `.github/`、`runs/`、`fixtures/out/`、`.tmp/` | — |

`tools/` 与 `tests/` **必须进 sdist**：README 的开发一节让人在解包目录跑这两条门与测试，不给就是"文档写了但树里没有"（阶段 7 的 ②③ 形态）。`.github/` 不进包（CI 只对仓库有意义）。

M6 的 `MANIFEST.in` 白名单按此表写，并由"M6 定版时解包 sdist 跑一遍两门 + 全量测试"这条动作核对（`plan/RELEASE-M6.md` §1.2：解包树布局门全绿 / 脱敏门 0 命中 / 211 passed —— **v0.1.0 时点值**；当前树值见 `plan/RELEASE-M6.1.md` §1.2）。

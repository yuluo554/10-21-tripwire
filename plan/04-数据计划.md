## 二、夹具 schema

### `orig.csv`

- UTF-8 **无 BOM**、LF 行尾、带表头。
- 列固定：`id, num_big, zip, decimal, exponent, date, text_unicode, nullable`（`id` 为主键，唯一、无前导零）。
- 三组样本池**混在同一张表**：用 `id` 前缀区分（`num-*` / `sem-*` / `ctl-*`），这样一条管线就能同时测三类。
- 200 行默认规模 = 60 numeric + 80 semantic + 60 control（比例写进生成器常量，测试断言）。

### `expected.json`

```json
{
  "seed": 42,
  "rows": 200,
  "generator_version": "0.1.0",
  "pools": {"numeric": 60, "semantic": 80, "control": 60},
  "cells": [
    {
      "cell": ["num-0001", "num_big"],
      "pool": "canary-numeric",
      "orig": "12345678901234567890",
      "rule": "scientific_notation_coercion",
      "p_after": {"pandas_csv": "1.2345678901234567e+19", "openpyxl_csv": "1.23457E+19"}
    }
  ]
}
```

**真值纪律（硬）**：

1. `expected.json` **只存输入与期望**，禁止出现 `observed_*` / `actual_*` 字段（出现即测试红）。
2. `p_after` 的期望值必须**由输入独立可算**（规则谓词 + 目标阶段的既定行为），不得由被测引擎跑一遍回填。
3. `control-lossless` 组的行**不出现在 `cells` 里**——它没有期望差异；门禁通过"该组上报差异数 == 0"来判。
4. 每条 `rule` 必须存在于 `rules.json`；生成器启动时断言。

### `manifest.json`

```json
{
  "seed": 42,
  "rows": 200,
  "generator_version": "0.1.0",
  "files": {"orig.csv": "<sha256>", "expected.json": "<sha256>"}
}
```

`manifest.json` 是**生成物**，不是手编文档；改生成器 → 必须整目录重生成。

## 三、三组样本池

| 池 | 数量（seed 42 / rows 200） | 取值来源 | 期望规则 |
|---|---|---|---|
| `canary-numeric` | 60 | 15/16/17/20 位整数；2^53、2^53+1；`1e-7`、`1E5`、`19.90`、`-0.00`、`1.005` | 数值族 8 条规则按谓词命中 |
| `canary-semantic` | 80 | `02114`、`00123-4567`、`NULL`/`''`/缺格、NFC/NFD `é`、`2024-01-02`、`1900-02-29`、`45293` | 空值 2 条 + 文本 4 条 + 时间 4 条 |
| `control-lossless` | 60 | 纯 ASCII 字母数字、无前导零、无小数尾零、无日期形态、无空白异常 | **无**（必须 0 差异） |

**控制组是硬约束**：它是"为防止为清零 unclassified 而放宽规则导致误报"的守门组（D4）。它一旦报出差异，precision 门必然失败。

## 四、真值覆盖口径

| 指标 | 定义位置 | 覆盖要求 |
|---|---|---|
| `recall` | `data/README.md` §6.2 | 分母 = `expected.json` 的 `cells` 条数；目标 1.0 |
| `precision` | 同上 | 分母 = 全部上报差异；目标 1.0（含 control 组零误报） |
| `unclassified` | 同上 | 条数；目标 0 |
| 规则覆盖 | `docs/rules.md` | 18 条每条至少 1 条正例 + 1 条反例；反例可以只存在于 `control-lossless` 池 |

**"未覆盖"要显式登记**：若某条规则在 seed 42 的样本里没有正例，生成器在 `expected.json` 的 `uncovered_rules` 列表里点名，且 `docs/rules.md` 如实标注——**不假装覆盖**。

---

## 五、确定性纪律

1. 生成器用**自研 splitmix64**（`fixtures.py` 内常量种子），**不用 `random` 全局状态**、不读系统时间、不依赖 `set` 迭代序。
2. 落盘一律 LF、UTF-8、无 BOM、无尾随空白；`orig.csv` 用 `csv.writer(lineterminator="\n")`。
3. **两层守门**：① 冻结产物形态（`fixtures/golden/` 内部自洽 + sha256 与 manifest 一致）；② 重跑生成器到临时目录 → 与冻结产物**逐字节 `cmp`**。
4. `--seed` / `--rows` 之外的参数**不参与**随机选择；新增参数若影响输出，必须同时进 manifest。
5. **部分运行不得改写全集清单**：`gen-fixture --pool numeric` 这类局部入口**不写** `manifest.json`（M4 实现时按 SKILL「生成器的部分运行」条落）。

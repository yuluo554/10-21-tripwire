# 01 · 题目文档 — 10-21-tripwire（结构化数据往返保真审计器）

> **性质**：不参赛项目题 · 发布 GitHub **公开仓库** · 署名 yuluo554 · 纯本地 Python CLI（零网络）
> **产出**：仓库 `10-21-tripwire`，命令行入口 `tripwire`
> **版本**：v1（2026-10-20 定稿；代理检索窗口 **2026-10-19T18:35Z–18:57Z**，本机本地时间 2026-10-20 02:35 UTC+8，UTC 仍在 10-19）
> **定位宣言**：一份数据经过 CSV→Excel→JSON→SQLite 转一圈，哪些值悄悄变了？本工具给**逐单元格差异 + 归因规则名 + 证据 + 出问题的环节**。现有工具要么只做两文件单元格差异但不解释原因（qsv diff / csvdiff / daff），要么只做单文件体检但不做往返对照（pandera / Great Expectations / Soda / frictionless）。本工具把"差异、归因、环节"三件事钉在同一条可复现管线上，并把 `unclassified` 当作一等公民而不是掩盖成"其他"。
> **口径声明**：`plan/01` 中的数值只写规则口径与门槛来源；一切可漂移的实现数字（测试条数、行数、覆盖率百分比）不在本文出现，由末态回填。

## 一、介绍

### 1.1 痛点：往返不是"读一下"，是"改一遍"

CSV 经过一次 Excel 打开另存，值就已经不是原来的值。这不是理论：本机用 **Microsoft Excel 16.0 Build 20326（COM 可用）** 现场复现，5 列 CSV 另存为 CSV 后，**4 行数据里 9 个单元格被改**（✅ 本机实测，本题核心证据）：

| 原始 | 往返后 | 判定 |
|---|---|---|
| `12345678901234567890` | `1.23457E+19` | 值不可恢复 |
| `02114` | `2114` | 前导零丢失 |
| `19.90` | `19.9` | 文本精度丢失 |
| `1e-7` | `1.00E-07`（自动套 `0.00E+00` 格式） | 表示形式改变 |
| `1234567890123456` | `1.23457E+15` | 16 位→失效 |
| `2024-01-02` | `2024/1/2` | 日期被本地化重写 |

同一批证据里还有三类"只比值比不出来"的情形（✅ 本机实测）：

- **文本型数字/格式即语义**：`'0123'` 带 `number_format='@'`、`0.15` 带 `'0%'` —— 值都是数字，语义全在 `number_format` 里；只比 value 会判成同一个。
- **隐藏行**：XML 里数据完好，openpyxl / calamine 照读 → 下游拿到"Excel 里看不见"的数据。
- **合并单元格**：`B2:C2` 合并后只有 B2 有值，C2 是 `MergedCell`、`value is None`。

需求不是孤例，GitHub / HN 上一线从业者的原话（✅ 逐条可直连）：

- HN 49182691："these ids will have been converted into scientific notation by Excel with the resulting loss of precision rendering the ids useless. We now do a cleaning step … `id_` is prepended" — https://news.ycombinator.com/item?id=49182691

- HN 39827143："some UPCs start with 0. Worst is when Excel saves the scientific notation back to the CSV, overwriting the correct number." — https://news.ycombinator.com/item?id=39827143
- HN 24070749："A CSV with zip codes, Excel drops the leading zero: Boston, 02114. A CSV with text ranges: 1-10, 11-20 … becomes 10-Jan and 20-Nov!" — https://news.ycombinator.com/item?id=24070749
- HN 32863855："Even just opening and accidentally saving … will step the leading zeros off in a CSV" — https://news.ycombinator.com/item?id=32863855

## 二、任务要求

**首期五个模块**（M1–M5）。每模块写明 输入 / 输出 / 引擎 / 确定性纪律。

### 模块 M1 · 往返管线执行器 + 逐段快照

- **输入**：原始 CSV（UTF-8，带表头）+ 管线声明文件 `pipelines/<name>.json`。
- **输出**：`runs/<run_id>/stage-<k>.csv`（**原始文本**，每阶段一份）+ `runs/<run_id>/stages.json`。
- **首期管线**（声明式，JSON，三族）：
  1. `csv→pandas→csv`（阶段名 `pandas_csv`）
  2. `csv→excel(COM)→csv`（阶段名 **`excel_com_csv`**）／`csv→openpyxl→csv`（阶段名 **`openpyxl_csv`**）
  3. `csv→json→sqlite→csv`（阶段名 `json_sqlite_csv`）
- **stages.json 每阶段必含**：列名与列类型、行数、列数、内容哈希（`sha256` of stage 文本）、该步运行时指纹（pandas 版本 / dtype 推断结果 / Excel 版本与 Build / openpyxl 版本 / SQLite 版本）。
- **确定性纪律**（硬）：
  - **快照存原始文本，不存 DataFrame**。存 DataFrame 就等于在落盘时先做了一次格式转换，比较之前已经丢过一次信息。
  - **`excel_com_csv` 与 `openpyxl_csv` 必须是两个不同的 stage 名**，报告只写实际跑的那个，**绝不混称"Excel"**。理由见 plan/00 决策记录 D1：openpyxl 写数字用 `%.16g`，与 Excel 的 15 位有效数字截断行为不同，混称会制造假阴性。
  - `run_id` 由管线名 + 输入文件内容哈希 + 声明文件哈希派生，**同一输入重跑得到同一 `run_id`**（不做时间戳命名）。
  - 缺依赖（如无 COM 环境）时该阶段**必须显式失败并记录**，不得跳过阶段后继续，也不得输出"无损"。

### 模块 M2 · 单元格级差异引擎

- **输入**：`stages.json` 引用的相邻两份 stage 快照（原文）。
- **输出**：`DiffRecord{row_key, col, orig_text, got_text, declared_type}` 列表 + 行列数/列顺序/表头三项结构差异。
- **对齐策略三选一**（`--align`）：
  - `key`：声明主键 `--key id`（**默认**策略）；
  - `position`：按 `(row, col)` 位置；
  - `lcs`：内容指纹 LCS。
- **必查项**：行数变化、列数变化、列顺序变化、表头变化。四项各自单独成记录，不折算进单元格差异率。
- **确定性纪律**（硬）：
  - **默认要求显式声明主键，未声明则拒绝运行**（exit 3，不产出任何"0 差异"结论）。这是 daff / csvdiff 类工具在插入行场景下的经典坑：位置对齐遇到插行会产生雪崩式误报，而工具仍报一个漂亮的差异数。
  - `--batch` 模式：吸收类型推断漂移——按 chunk 分别记录 dtype，同一列在不同 chunk 推断不一致时落为结构记录（pandas 文档原文 "possibly mixed type inference"，✅ 本机实测同列 6 个 chunk 里 1 个是 `str`）。
  - 差异记录**排序稳定**（按 `row_key`、再按列序），保证同一输入两次运行输出逐字节一致。

### 模块 M3 · 归因规则引擎（首期 18 条，四族）

归因**不是猜**：规则只给 `possible_stages` 候选集，最终环节由 M1 的快照序列**筛掉**不可能的阶段。

**规则表（口径见 `data/README.md` 第六节，代码只引用）**：

| # | 族 | 规则名 | 谓词要点（orig→got） | possible_stages |
|---|---|---|---|---|
| 1 | 数值 | `leading_zero_lost` | 原文匹配 `0\d+`，往返后为同值整数形式（去零后数值相等） | excel_com_csv / openpyxl_csv / json_sqlite_csv / pandas_csv |
| 2 | 数值 | `scientific_notation_coercion` | 原文纯数字串，往返后匹配 `\d(\.\d+)?E[+-]\d+` 且数值等价 | excel_com_csv / openpyxl_csv / pandas_csv |
| 3 | 数值 | `float_precision_truncated` | 原文为定点小数，往返后有效数字位数减少且数值不严格相等 | pandas_csv / json_sqlite_csv / openpyxl_csv |
| 4 | 数值 | `int53_overflow` | 原文整数绝对值 > 2^53−1，往返后不相等 | json_sqlite_csv / excel_com_csv |
| 5 | 数值 | `excel_15_digit_truncation` | 原文整数有效位 > 15，往返后末位起被置零 | excel_com_csv（**仅此阶段可归因**） |
| 6 | 数值 | `negative_zero_sign_lost` | 原文匹配 `-0(\.0+)?`，往返后为 `0` 或无符号同值 | excel_com_csv / json_sqlite_csv / pandas_csv |
| 7 | 数值 | `decimal_trailing_zero_dropped` | 原文含尾随零小数，往返后数值相等但文本精度更短 | excel_com_csv / pandas_csv / json_sqlite_csv |
| 8 | 数值 | `exponent_form_normalized` | 原文含指数（如 `1e-7`），往返后指数大小写/补零/格式改变而数值相等 | excel_com_csv / openpyxl_csv |
| 9 | 空值 | `empty_vs_null_vs_missing` | 空串 / `None` / 缺格三者之一变成另一种 | pandas_csv / json_sqlite_csv |
| 10 | 空值 | `null_token_collision` | 原文为 `NULL`/`N/A`/`NaN`/`None`/`#N/A` 等字面量，往返后塌缩为缺失 | pandas_csv / json_sqlite_csv |
| 11 | 文本 | `unicode_normalization_changed` | NFC/NFD 等价但码点序列不同 | pandas_csv / openpyxl_csv / json_sqlite_csv |
| 12 | 文本 | `whitespace_collapsed` | 首尾空白被裁或连续空白被压缩 | pandas_csv / openpyxl_csv |
| 13 | 文本 | `bom_prepended` | 往返后文本以 `U+FEFF` 开头 | openpyxl_csv / pandas_csv |
| 14 | 文本 | `encoding_mojibake` | 往返后出现典型替换字符/乱码序列（**只检出，不修复**） | 任一阶段 |
| 15 | 时间 | `date_retyped_to_text` | 原文日期形态，往返后为另一种文本日期形态（如 `2024-01-02`→`2024/1/2`） | excel_com_csv / pandas_csv |
| 16 | 时间 | `date_system_shift_1904` | 同一 serial 在 1900/1904 两纪元下相差 1462 天，或切换后显示日期整体偏移 | excel_com_csv |
| 17 | 时间 | `serial_60_phantom_date` | serial 60 被渲染为 `1900-02-29`（Excel 1900 闰年 bug） | excel_com_csv |
| 18 | 时间 | `number_format_dropped` | 值相同但 `number_format` 语义丢失（如 `0%`、`@` 变 General） | excel_com_csv / openpyxl_csv |

- **输出**：`Attribution{rule, first_seen_at, candidates, resolved_stage, evidence}`。
- **日志格式（写死）**：`rule=<name>, first_seen_at=stage 2 (excel_com_csv), candidates=[...] -> resolved to excel_com_csv`。
- **`unclassified` 是一等公民**：不塞进"其他"，单独计数、单独列出、可 `--fail-on unclassified`。
- **确定性纪律**（硬）：
  - 规则只允许**纯函数谓词**（orig_text, got_text, declared_type, stage 指纹）→ 输出，不得读网络、不得读时钟。
  - 一条差异命中多条规则时按规则编号升序取首条，**并在 evidence 里列出其余命中**（不静默丢弃）。
  - 归因上限是"**环节**"，不是"代码行"。README 必须写死这一句，否则承诺落空。
  - 验收（原型已达成，✅）：14 单元格 / 9 条差异 / **9 条全部命中命名规则，unclassified = 0**。

### 模块 M4 · 真值夹具生成器

- **命令**：`tripwire gen-fixture --seed 42 --rows 200`
- **输出**：`orig.csv` + `expected.json`，`expected.json` 每条为 `{cell, orig, rule, p_after{stage: val}}`。
- **三组样本池**（全程序化生成，`--seed` 决定全部随机选择）：
  - `canary-numeric`：15/16/17/20 位整数、2^53 与 2^53+1、`1e-7`、`1E5`、`19.90`、`-0.00`、`1.005`
  - `canary-semantic`：`02114`、`00123-4567`、`NULL`/`''`/缺格 三态、NFC/NFD `é`、`2024-01-02`、`1900-02-29`、`45293`
  - `control-lossless`：**测误报，必须为 0 条差异**
- **门禁三数**：`recall==1.0 && precision==1.0 && unclassified==0`，打印在报告首屏；**任一不满足 exit 2**。
- **确定性纪律**（硬）：
  - 同一 `--seed` 与 `--rows` 生成**逐字节一致**的 `orig.csv` 与 `expected.json`；生成器不读系统时间、不读 `random` 的全局状态。
  - `control-lossless` 组是**硬约束**：为防止"为清零 unclassified 而放宽规则导致误报"，该组 precision 恒须为 1.0。
  - 夹具全为合成值（假邮编、假 URL、假标识），不含任何真实个人或商户数据。

### 模块 M5 · 报告与 CI 出口

- **输出**：Markdown（人读）、JSON（机读）、SARIF（CI 注解）三份，同一 `run_id` 下同源。
- **首屏固定三段（顺序与字面固定）**：
  ```
  VERDICT: LOSSY (37/1200 cells, 5 rules)
  FIRST LOSS AT: stage 2 = excel_csv (Excel 16.0 Build 20326)
  GATE: recall 1.00 precision 1.00 unclassified 0
  ```
  （数值为示例形态，实际由本次运行计算；阶段名必须是 M1 的真实 stage 名。）
- **退出码**（判定通道 0/1/2，用法通道 3，不计入判定）：
  - `0` 无损
  - `1` 有损
  - `2` 门禁失败（M4 三数任一不满足）
  - `3` 用法错误 / 拒绝运行（未声明主键、管线声明非法、缺依赖）
- **每条 finding 带稳定 `fingerprint`**（由 `row_key + col + rule` 派生，不含时间戳），可跨 run diff。
- **确定性纪律**：报告渲染不得读取时钟或随机数；MD/JSON/SARIF 三份的差异集合必须来自同一内存结果（先算一次再渲染三次）。

### 扩展项（二期，首期不做）

- **YAML / TOML / MessagePack 通道**：作为**数据通道**（对象是数据值本身），不是配置文件 diff；二期接入。**首期管线不含 YAML/TOML 配置**（见 §六）。
- **LibreOffice 通道**：`libreoffice_csv` stage 名预留，⬜ 本机未实测，不得在首期报告里出现"已验证"措辞。

## 六、边界与非目标

**不做（首期红线）**：

1. **不做编码修复** —— `encoding_mojibake` 只检出、只定位环节，不猜原编码、不写回文件。（与既有"编码/乱码"类需求切割：那是修复工具，这是审计器。）
2. **不做文档去重 / 相似度** —— 不引入任何相似度阈值或聚类。
3. **不做金额语义对账** —— 不判"这笔账对不对"，只判"这个单元格的值变没变"。
4. **管线不含 YAML/TOML 配置** —— 三族管线只处理 CSV/XLSX/JSON/SQLite 四类**数据通道**；不读、不比、不 diff 任何配置文件。
5. **不解析 SQL** —— SQLite 阶段只做"写入→读回"的往返，不分析 SQL 语句、不做血缘。
6. **不校验 schema 兼容性** —— 只报"值变了/结构变了"，不判"新旧 schema 是否兼容"。
7. **不做"智能猜测对齐"** —— 无主键宁可拒绝运行（exit 3），不猜行对应关系。
8. **归因上限是"环节"不是"代码行"** —— 报告只指到 stage，不指到源码行号；README 必须写死这一句。
9. **不做自动修复 / 不写回源文件** —— 工具只读输入、只写 `runs/`。

**隐私红线**：纯本地、零网络（含零遥测、零版本检查）；夹具全部合成；`runs/` 默认被 `.gitignore` 排除，避免把真实数据误提交。

**品牌隔离**：本仓库文档不提及任何姊妹项目；涉及同系列时一律用方向级描述，不落具体领域名词。

**首期范围限定**：四通道（CSV/XLSX/JSON/SQLite）、五模块、18 条规则。YAML/TOML/MessagePack 与 LibreOffice 通道为二期。

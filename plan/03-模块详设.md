## M1 · 往返管线执行器 + 逐段快照

### 接口

```python
# tripwire/pipeline/schema.py
def load_pipeline(path: Path) -> PipelineDecl        # 非法声明 -> raise PipelineDeclError（CLI 转 exit 3）
def validate_pipeline(decl: PipelineDecl) -> list[str]  # 返回问题列表；空 = 合法

# tripwire/pipeline/runner.py
def run_pipeline(decl: PipelineDecl, input_csv: Path, out_dir: Path) -> RunStages
```

`PipelineDecl` 形状（`pipelines/*.json`）：

```json
{
  "name": "excel_com",
  "input": "csv",
  "stages": [{"stage_name": "excel_com_csv", "engine": "excel_com"}],
  "schema_version": 1
}
```

### 阶段实现

| stage_name | 引擎 | 输入 | 输出 | 依赖 |
|---|---|---|---|---|
| `pandas_csv` | `pandas.read_csv` → `to_csv` | stage 文本 | stage 文本 | pandas |
| `excel_com_csv` | Excel COM：打开 CSV → SaveAs CSV | stage 文本 | stage 文本 | Windows + Excel + pywin32 |
| `openpyxl_csv` | 读 CSV → xlsx → 读回 → 写 CSV | stage 文本 | stage 文本 | openpyxl |
| `json_sqlite_csv` | CSV → JSON 数组 → SQLite 表 → 查询 → CSV | stage 文本 | stage 文本 | stdlib |

**每阶段输出一律为原始文本**：阶段实现负责把结果写成 `stage-<k>.csv`，**不得**把 DataFrame 交给上层（K1）。

### 失败路径（硬）

- 缺依赖（无 COM / 无 pandas / 无 openpyxl）→ `StageUnavailable(stage_name, reason)` → CLI **exit 3**，并在 `stages.json` 写入 `{"stage_name": ..., "status": "failed", "reason": ...}` 后**终止整条管线**。
- **禁止**：失败后跳过该阶段继续、把失败阶段计为"无损"、静默回落到另一个引擎（D1）。
- 输出目录已存在同 `run_id` → 复用（幂等），但若 `stages.json` 内容不同则报 `RunIdCollision`（exit 3）——同 id 必须同内容。

### 测试点

- `test_three_families_produce_stages`：三条声明各跑一次，stage 数正确。
- `test_stage_text_sha256_matches`：快照 sha256 复算一致。
- `test_runtime_fingerprint_fields`：`runtime` 键齐全，不适用字段为 `null` 而非缺键。
- `test_same_input_same_run_id`：同输入两次 → 同 `run_id`。
- `test_missing_engine_fails_loudly`：monkeypatch 使 `excel_com` 不可用 → exit 3 且 `stages.json` 有 `failed` 记录。

## M2 · 单元格级差异引擎

### 接口

```python
# tripwire/diff/align.py
def align(orig: CsvTable, got: CsvTable, strategy: str, key: str | None) -> list[tuple[int|None, int|None]]

# tripwire/diff/engine.py
def diff_tables(orig: CsvTable, got: CsvTable, *, strategy: str, key: str | None,
                batch: int | None = None) -> DiffResult   # DiffResult(diffs, structures)
```

### 对齐策略

| `--align` | 语义 | 默认 | 前提 |
|---|---|---|---|
| `key` | 按 `--key` 列值对齐 | ✅ | 必须给 `--key`，否则 **exit 3**（K4） |
| `position` | 按 `(row, col)` | | 显式指定；报告中标注"位置对齐，插行会产生连带差异" |
| `lcs` | 行内容指纹的精确 LCS | | 不做相似度、不做阈值 |

`row_key` 在 `key` 策略下 = 主键值文本；`position` 下 = `#<row_index>`；`lcs` 下 = 匹配到的原行指纹。**`row_key` 参与 `fingerprint`**，因此策略不同 → fingerprint 不同（期望行为，报告里写明策略）。

**`lcs` 的锚点与空隙（M2 落地时的补充口径）**：只靠精确指纹锚点，配上的行按定义逐字节相同，`lcs` 就永远报不出单元格差异。因此锚点只定"哪些行确定没动"，**锚点之间的空隙按位置成对**——改动的行落在它该落的位置，插进来的行留作单边（进 `row_count` 记录）。这不是相似度：空隙配对不做任何内容比较，只按序号。

### 结构差异（四项独立成记录，不折算进单元格差异率）

`row_count` / `col_count` / `col_order` / `header`。`--batch N` 额外产出 `dtype_drift`（同列在不同 chunk 推断不一致）。

### 失败路径

- 未给 `--key` 且策略为 `key` → exit 3，**不产出任何 `diffs: []` 结论**（K4）。
- `--key` 指定的列不存在于任一快照 → exit 3，报列名。
- 主键重复 → exit 3（重复键无法建立一对一映射；不"取第一个"）。

### 测试点

- `test_prototype_nine_diffs`：原型 14 单元格样本 → 9 条差异。
- `test_prototype_diffs_are_the_expected_cells`：不只数条数，逐条钉 `(row_key, col)` 与两侧文本。
- `test_prototype_nine_diffs_on_real_excel`：同一样本走真机 `excel_com_csv` 再比对（不可用时显式 skip）。
- `test_structure_changes_reported_separately`：行/列/列序/表头各一条。
- `test_no_key_refuses_to_run`：exit 3。
- `test_duplicate_key_refuses_to_run`：exit 3。
- `test_diff_order_stable`：两次运行序列化逐字节一致。

## M3 · 归因规则引擎

### 数据形状（`src/tripwire/rules/rules.json`）

```json
{
  "schema_version": 1,
  "rules": [
    {
      "id": 1,
      "family": "numeric",
      "name": "leading_zero_lost",
      "predicate": "leading_zero_lost",
      "possible_stages": ["excel_com_csv", "openpyxl_csv", "json_sqlite_csv", "pandas_csv"],
      "evidence_required": ["orig_text", "got_text"],
      "counterexample": "orig='0', got='0' -> 不命中（无丢失）"
    }
  ]
}
```

`predicate` 是 `predicates.py` 里的**函数名**；`rules.json` 只是清单，不内嵌表达式（避免"规则即代码"的沙箱问题）。

### 归因流程

1. 对每条 `DiffRecord`，按 `id` 升序跑谓词，收集命中集合；
2. 取**首条**为 `rule`，其余写 `evidence.also_matched`；
3. `candidates = 首条规则的 possible_stages`；
4. **用 M1 的 stage 序列筛掉不可能的阶段**：从 `stage-0` 起逐阶段比较该单元格文本，找到**首次出现 `got_text` 的相邻阶段**，若该阶段名 ∈ `candidates` → `resolved_stage = 该阶段`；否则在 `candidates` 中按**实际运行顺序**取最早者；若 `candidates` 与该 run 的 stage 名**无交集** → `resolved_stage = null` 且 `rule` 降级为 `unclassified`（**宁可 unclassified，不伪造归因**，D1）。
5. 无任何谓词命中 → `rule = "unclassified"`，`resolved_stage = null`，仍计入 `attributions` 并单独计数。

### `--explain` 日志（格式写死）

```
rule=<name>, first_seen_at=stage 2 (excel_com_csv), candidates=[excel_com_csv, openpyxl_csv] -> resolved to excel_com_csv
```

`first_seen_at` 的 `stage <k>` 取 1-based 的**输出阶段序号**（stage-1 是第一份输出），与 `stages.json` 的 `stage_index` 一致。

### 测试点

- `test_rules_table_has_18`：`rules.json` 恰好 18 条、四族计数 8/2/4/4、每条 predicate 在 `predicates.py` 里存在。
- `test_nine_of_nine_classified`：原型 9 条差异全部命中命名规则，`unclassified == 0`。
- `test_every_attribution_has_evidence`：`orig_text/got_text/stage_meta` 非空。
- `test_first_seen_stage_from_snapshot_sequence`：构造"同规则不同环节"两例，`resolved_stage` 不同。
- `test_candidate_stage_not_in_run_degrades_to_unclassified`：openpyxl 跑出的 15 位截断不得归因到 `excel_15_digit_truncation`。
- `test_also_matched_recorded`：一条差异命中多规则时其余命中不丢。

## M4 · 真值夹具生成器 + 门禁

### 接口

```python
# tripwire/fixtures.py
def generate(seed: int, rows: int, out_dir: Path) -> FixtureResult   # 写 orig.csv + expected.json
# tripwire/gate.py
def compute_gate(expected: list[Expected], attributions: list[Attribution]) -> Gate
```

`expected.json` 每条：`{"cell": [row_key, col], "orig": "...", "rule": "...", "p_after": {"<stage_name>": "..."}}`。

### 三组样本池（构造纪律见 `docs/fixture-pools.md`）

| 组 | 内容 | 期望 |
|---|---|---|
| `canary-numeric` | 15/16/17/20 位整数、2^53、2^53+1、`1e-7`、`1E5`、`19.90`、`-0.00`、`1.005` | 逐条命中数值族规则 |
| `canary-semantic` | `02114`、`00123-4567`、`NULL`/`''`/缺格、NFC/NFD `é`、`2024-01-02`、`1900-02-29`、`45293` | 逐条命中空值/文本/时间族规则 |
| `control-lossless` | 纯 ASCII、无前导零、无小数尾零、无日期 | **0 条差异**（precision 硬约束） |

### 门禁三数

`recall / precision / unclassified` 的定义**只在 `data/README.md` §6.2**；`gate.py` 只实现不复述。任一不满足 → exit 2。

### 测试点

- `test_same_seed_byte_identical`：两次生成 `cmp` 一致（**两层**：冻结产物形态 + 重跑生成器到临时目录比对）。
- `test_control_lossless_zero_false_positive`：该组 0 差异。
- `test_gate_three_numbers_printed_on_first_screen`。
- `test_gate_failure_exits_2`。
- `test_golden_matches_generator`：`fixtures/golden/` 与 `--seed 42 --rows 200` 重生成逐字节一致。

## M5 · 报告与 CI 出口

### 接口

```python
# tripwire/report/model.py
def build_run_result(...) -> RunResult
# tripwire/report/render_{md,json,sarif}.py
def render(result: RunResult) -> str
```

### 首屏三段（顺序与字面固定）

```
VERDICT: LOSSY (37/1200 cells, 5 rules)
FIRST LOSS AT: stage 2 = excel_com_csv (Excel 16.0 Build 20326)
GATE: recall 1.00 precision 1.00 unclassified 0
```

- 无损时 `VERDICT: LOSSLESS (0/1200 cells, 0 rules)`；
- `FIRST LOSS AT` 的阶段名必须是 M1 的真实 stage 名（`openpyxl_csv` 不得写成 `excel_csv`）；
- 括号内运行时指纹在该阶段 `runtime` 为空时写 `unknown`，**不省略整行**。

### SARIF

`version: 2.1.0`，`runs[0].results[*]` 每条 finding 一个 `result`：`ruleId = 规则名`、`level = warning`、`partialFingerprints.primaryLocationLineHash = fingerprint`、`locations[0].physicalLocation.artifactLocation.uri = "stage-<k>.csv"`。**不写绝对路径**。

### 退出码测试（交付态四条）

`tests/test_exit_codes.py`：0 / 1 / 2 / 3 各一条，全部走**真实 CLI 入口**（`subprocess` 或 `main(argv)`），断言 `main` 返回值与进程退出码一致。

### 测试点

- `test_three_formats_same_findings`：MD/JSON/SARIF 的 finding 集合按 fingerprint 相等。
- `test_first_screen_three_lines`：字面与顺序。
- `test_fingerprint_stable_across_runs`：同输入两次 run 的 fingerprint 集合相等。
- `test_render_is_clock_free`：两次渲染逐字节一致；AST 扫描渲染模块无 `datetime/time/random`。
- `test_no_network_imports`：AST 扫描 `src/tripwire` 无网络库。
